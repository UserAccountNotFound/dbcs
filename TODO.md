# Безопасность
### безопасность должна быть не отдельным этапом, а частью архитектуры!
  ## Аутентификация
  - Короткоживущий access token в памяти frontend-приложения.
    - !!! access token не стоит хранить  в localStorage: --> риск при XSS
  - Refresh token в HttpOnly, Secure, SameSite=Lax/Strict cookie.
  - Ротация refresh token.
  - Возможность отозвать любую сессию.
  - Опционально TOTP MFA.

  ## Авторизация
  - Нужно явно разделить права:
    - пользователь видит только свои визитки;
    - админ видит управление пользователями и шаблонами;
    - публичный API отдает только активные визитки;
    - проверка владения ресурсом обязательна на backend.

   ## Nginx
   - fail2ban
   - limit_req
   - headers:
     
  ```
  Strict-Transport-Security
  Content-Security-Policy
  X-Content-Type-Options: nosniff
  Referrer-Policy
  Permissions-Policy
  Cross-Origin-Opener-Policy
  Cross-Origin-Resource-Policy
  ```

# Шаблоны дизайна
Чтобы сохранить гибкость, но не получить XSS и неконтролируемый CSS, делаем так:
- Шаблоны хранятся в БД как метаданные.
- Реальный рендер шаблонов находится во frontend как набор Vue-компонентов.
- Пользователь выбирает template_code.
- Пользователь может менять только разрешенные параметры:
- цветовая схема;
- акцентный цвет;
- шрифт из списка;
- расположение блоков;
- отображаемые поля
